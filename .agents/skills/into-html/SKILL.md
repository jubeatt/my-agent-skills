# Into HTML

把輸入的資訊**重組**成一份單檔 HTML：讀者打開就能快速掌握重點、跳轉查找、按需展開細節。目標是閱讀體驗，不是格式轉換。

## 流程

### 1. 蒐集輸入

輸入有兩類：使用者指定的外部資源（一份或多份文件、URL），或當下 session 的討論內容。兩者可以並存。**完成判準**：每份指定的資源都已完整讀過，並列出這份 HTML 的來源清單（檔案路徑、URL、或「本次對話」）。

### 2. 重組內容

依性質分類，同類的東西放在一起，順序以讀者理解的路徑為準，不必沿用原文結構。重組的界線：

- **事實不遺漏、不改寫原意**：重排、合併、換句話說都可以，資訊本身要完整保留。
- **推論要標註**：原文沒有、由 agent 推得的結論或建議，在 HTML 中明確標成補充。
- **次要細節收起來**：不重要的細節放進手風琴，保留在頁面上。

**完成判準**：輸入中的每一項事實都能在大綱裡找到位置。

### 3. 挑選呈現元素

讀 [`ELEMENTS.md`](ELEMENTS.md)。基本規則全部套用；可選元素依選用表逐一判斷，只挑內容真正需要的。**完成判準**：每個選用的元素都能指出它對應到的具體內容（例如「第 3 節有 40 列 API 清單 → 互動表格」）。

### 4. 寫出 HTML

- **位置**：使用者有指定就照指定。否則在 git repo 裡放 repo root，不在 repo 裡放 `/tmp`。
- **檔名**：`<slug>.html`，slug 是描述主題的 kebab-case。同名檔案已存在、且不是這次對話產的，就換一個 slug。

### 5. 驗證互動

頁面用到互動表格、tabs 這類有狀態的 JS 元素時，用 ego-browser 打開實測。**完成判準**：console 沒有錯誤，每種互動都實際操作過一次且結果正確，錨點跳轉後的目標沒被遮住。沒有這類元素、或 ego-browser 不能用時，跳過此步。

### 6. 交付

用 `open` 在預設瀏覽器打開，並回報檔案的完整路徑。
